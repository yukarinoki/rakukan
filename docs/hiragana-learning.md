# ひらがな確定の学習

## 設定画面で学習履歴を管理する

サイドバーの「学習履歴」で、読み・表記による検索と最終使用日時の確認ができる。
一覧はウィンドウ内でスクロールし、編集時だけ小さなダイアログを開く。

- **追加・編集**: 読みと表記を入力して「優先して保存」。同じ読みの学習候補より
  高いスコアで保存する。例えば「あるの → あるの」を追加すれば、既存の
  「あるの → アルノ」の頻度が高くても、ひらがなを優先できる。
- **優先する**: 選択した表記をそのまま優先する。永続的な固定ではなく、以後も
  通常の学習・減衰が適用される。ユーザー辞書の候補は引き続き最優先。
- **削除**: 選択した1件だけ学習履歴から削除する。確認ダイアログを表示する。
  システム辞書から消す操作ではなく、その候補を再確定すると再び学習される。
- **再読み込み**: 設定画面を開いている間に増えた履歴を読み直す。

履歴の操作は即時保存され、次の変換から反映される。自動学習の ON/OFF は
従来と同じく設定画面の「保存して閉じる」で保存する。

設定アプリは `rakukan-engine-host --manage-learning` の標準入出力で JSON を
送受信し、既存の Named Pipe へ接続する。管理用の接続は `Create` を送らず、
変換中の入力・設定をリセットしない。実行中のエンジンが持つ最新の学習履歴を
操作し、古いファイル全体の上書きを避ける。変更は永続化成功後にメモリへ反映する。
通信結果が不明な場合は変更要求を自動再送せず、UI で再読み込みを案内する。
旧 DLL の場合は未対応エラーを表示する。

## 自動学習の修正

`auto_learn = true` の場合、候補から読みと同じひらがなを選んで確定したときも
学習履歴に記録する。F6 または変換取り消しでひらがな表示に戻して Enter で
確定する場合も対象。ライブ変換では、学習により先頭になったひらがな候補を
飛ばさず表示する。

従来は TSF の `text == reading` ガードと辞書のひらがな拒否により、
「あるの → アルノ」は学習されても「あるの → あるの」は学習されなかった。
さらに、通常の未変換文字列を Enter で確定する経路は学習を呼んでいなかった。

辞書登録なしで許可する同一表記は、空でないひらがな（長音・踊り字を含む）。
読みと異なる辞書外のひらがな・漢字に対するガード、学習 OFF、再変換の
学習除外は維持する。待機中の仮表示を急いで確定する経路や、ライブ変換が
未収束の場合の学習規則は変更しない。

保存形式と頻度・経過時間による順位計算は変更しない。過去に多く確定した
表記がある場合、新しい表記を一度確定しても先頭になるとは限らない。
既存の学習ファイルを削除・補正する必要はない。

回帰テストは TSF の学習可否、辞書未登録の同一ひらがなの保存と再読み込み、
「アルノ」5回に対する「あるの」6回の順位、エンジンの候補統合、ライブ候補
選択を確認する。実際のアプリでのキー操作確認には新しい TSF DLL の読み込みが必要。

## 検証

- Rust: 辞書・エンジン・RPC・TSF の単体テスト 351 件成功。
- WinUI: Release ビルド成功（警告・エラーなし）。設定テストで日本語 JSON、
  検索、エラー応答、旧ホストの空応答も確認。
- `python scripts/test_learning_management.py --build-dir C:\rb\release`:
  専用 APPDATA / LOCALAPPDATA / パイプを使い、実ホスト・RPC・DLL 経由で
  一覧、追加・優先、編集、入力エラー、削除、再起動後の永続化を確認。
- Computer Use の接続エラーにより、実ウィンドウの視覚確認・キー操作は未確認。
