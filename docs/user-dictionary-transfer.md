# ユーザー辞書のインポート・エクスポート

設定アプリの「ユーザー辞書」から「インポート…」を選択します。
読み込んだ単語は既存の項目へ追加され、同じ読み・単語の組はスキップされます。
既存の候補順・品詞・コメントは維持します。「保存」または設定画面を閉じると反映します。

「エクスポート…」は、保存前の編集も含めた一覧全体を書き出します。

## テキスト形式

1 行につき `読み<TAB>単語<TAB>品詞<TAB>コメント`。
品詞・コメントは省略可能で、省略時の品詞は「名詞」です。
空行、および空白を除いて `!` または `#` で始まるヘッダー行は無視します。
不正な行があれば行番号を表示し、そのファイルからは何も追加しません。

- 入力: BOM 付き UTF-16 LE/BE、UTF-8、Shift_JIS (Windows-31J)。
- 出力: BOM 付き UTF-16 LE、CRLF、タブ区切り。コメントが空の語は 3 列。
- 品詞とコメントは内部 TOML の `parts_of_speech` / `comments` に候補順で保存します。
  現在の変換エンジンは読みと単語を使用し、品詞による活用処理は行いません。
- 内部形式の `user_dict.toml` を直接取り込む機能ではありません。

辞書だけの変更でも、保存の再読み込み通知によりホストを再起動します。
設定と辞書の両方が同じ場合は再起動しません。この判定には更新済みのエンジンホストが必要です。

## 検証

`dotnet run --project apps/rakukan-settings-tests` で文字コード、品詞・コメントの保持、
重複、エラー処理、TOML 経由の往復を検証します。末尾に `-- <辞書ファイルのパス>` を
渡すと、そのファイルのバイト単位の往復一致も検証します（UTF-16 LE / CRLF / 3〜4 列）。

Rust の `dictionary_change_restarts_host_even_when_config_is_unchanged` は、
設定が同じでも辞書が異なれば再起動し、読み込み後は再起動しないことを確認します。
