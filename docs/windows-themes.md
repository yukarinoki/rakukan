# Windows のテーマとキー割り当ての修正

## ライト / ダーク

- 候補ウィンドウの白背景固定を解消し、通常行・選択行・ステータス・ページ行を
  アプリ用テーマ (`AppsUseLightTheme`) に合わせる。
- カーソル下の「あ / A」もアプリ用テーマを使う。
- タスクバー上のアイコンはタスクバー用テーマ (`SystemUsesLightTheme`) を使う。
  非表示のトップレベルウィンドウで設定変更通知を受け、アイコンの更新を通知する。
- 表示中の候補とモード表示は `WM_SETTINGCHANGE` / `WM_THEMECHANGED` /
  `WM_SYSCOLORCHANGE` で再描画する。
- 設定画面は XAML のテーマ背景を使い、`ActualThemeChanged` と起動・再アクティブ時に
  ネイティブのタイトルバーも同期する。

TSF を読み込んだ相手アプリ全体のテーマを変更する API は呼ばない。
タイトルバーの扱いは [Microsoft の Win32 テーマ対応ガイド](https://learn.microsoft.com/ja-jp/windows/apps/desktop/modernize/ui/apply-windows-themes) を参照。

配色のコントラストとアプリ / タスクバーの設定分離を含む TSF テスト 111 件が成功。
WinUI Release ビルドも成功。実際の Windows テーマ切り替えと画面の目視確認は未実施。

## Henkan の IME ON 割り当て

設定 UI の主要キーを変更しても、非表示の追加キーが保存ファイルに残っていた。
例えば `Henkan → ime_on` の後に `Henkan → convert` が保存されると、TSF の
後勝ちルールで変換開始が優先され、IME OFF 中は ON にできなかった。

保存時は、画面の主要キーと衝突する追加キー・その他の割り当てを取り除く。
主要キー同士の重複は保存前にエラーとする。無関係な追加キーは保持する。
初期設定の UI への反映中に、プリセット変更イベントが既定値を再代入することも防ぐ。

設定テストで Henkan の競合除去、無関係なキーの保持、保存・再読み込みの安定性、
主要キーの重複拒否を確認した。既存ファイルの競合は保存し直すことで修復される。
