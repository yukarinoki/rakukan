# AIモード

設定の「AIモード」で有効にします。有効化スイッチは切り替えた時点でAI設定を保存し、反映します。初期状態はオフ、接続先は軽量ローカルGGUF（Qwen3.5-2B Q4_K_M）です。ダウンロード前でもオフの設定を保存できます。有効化や接続確認にはモデルとサーバーの取得が必要です。既存の保存済み設定は維持します。初期状態はオフなので、既存のキー割り当ては有効化するまで変わりません。
既定のAIキーは Henkan。有効時はIMEのオン／オフに関係なくAIキーが優先されます。
HenkanのIME ON割り当ては使われなくなるため、ひらがなキーなどを使用してください。
選択範囲の再変換は Ctrl+Shift+R で引き続き利用できます。

## 操作

- アプリで選択した文章、または未確定の全文を対象にします。確定済みの周囲の文章は自動取得しません。
- 対象が空のときはAIモードに入りません。AIキーでキャレットの右に小さな半透明の青い入力領域を開きます。自動生成はせず、指示を入力してEnterを押すまで待機します。説明文や候補番号は表示しません。
- 青い領域に指示を入力すると、本文の行高を保って右へ広がります。指示は小さめ、候補は取得できれば入力欄のフォントを使用し、取得できなければ本文のキャレット高を文字の高さとして表示します。置換候補の下だけは、元の文字が透けないよう不透明にします。生成中は白くゆっくり脈動し、完成すると候補を表示します。置換候補は対象の元の文字を青く覆って重ねます。アプリの文章は採用まで変更しません。
- プレビューは独立した重ね表示で、アプリの段落の折り返し自体は採用まで変えません。長い候補はPgUp/PgDnで表示を切り替えます。対象が画面外・レイアウト取得不可の間は重ね表示を隠します。
- 候補の右に少し間隔を空けた小さな水たまりで追加指示を入力します。候補は追加指示の入力中・生成中も残ります。画面右端に収まらない場合は候補の下に表示します。ローマ字はひらがなになり、Spaceで辞書変換できます。
- 指示を入力してEnterで生成。指示追加がなければEnterで結果を採用します。生成中の空Enterは採用しません。
- Tabは指示済みの場合に同じ指示で別候補を生成します。空の状態ではEnterもTabも生成しません。PgUp/PgDnで長い結果を読み、Escで取り消せます。
- 「えいご」「丁寧」「メール」などの登録コマンドは、設定で名前・別名・指示・言語・追記／置換を編集できます。
- 自由指示は直前の候補を補正します。直前の追記／置換と言語を引き継ぎます。言語変更は対応する登録コマンドを使用してください。
- フォーカス変更、対象の変更、読み取り専用・パスワード欄への反映は拒否します。対象は最大8192 UTF-16コード単位です。

## 接続方式

### Copilot Keyboard共有

Copilot Keyboard の起動中のモデルへ接続します。rakukan側でモデルを読み込まないため、モデルを二重起動しません。
確認した構成は CopilotKeyboardLMServer **1.0.0.11040**、**qwen3-8b / CPU** です。
未公開の `AITextService` 名前付きパイプを使うため、Copilotの更新によって非対応になる可能性があります。
接続できなくても、別モデルへの切り替え、Copilotの起動・再起動、レジストリ変更、モデルダウンロードはしません。

「接続確認」はモデル名・ハードウェア・保存状態を表示します。「生成を試す」は画面の文章と指示で実際に生成します。
保存状態 `Downloaded` は生成可能であることを保証しません。生成テストも確認してください。
このインターフェースは完成結果を返します。生成上限・ストリーミング・モデル読み込み時間の内訳は取得／制御できません。
取り消すと結果を破棄して接続を閉じますが、Copilot側の計算が直ちに停止する保証はありません。
Copilot自身の診断ログはCopilotの設定に従います。

### ローカルGGUF

設定の「ローカル GGUF（llama-server）」で「ダウンロードして使う」を押すと、モデルとCPUサーバーを取得してパスを保存します。
- Qwen3.5-2B Q4_K_M：約1.4GB。標準の軽量モデル。
- Qwen3.5-0.8B Q4_K_M：約580MB。速度優先で、書き換えの正確さは2Bより劣る場合があります。

モデルは [bartowskiのGGUF](https://huggingface.co/bartowski/Qwen_Qwen3.5-2B-GGUF)、CPUサーバーは [llama.cpp b10869](https://github.com/ggml-org/llama.cpp/releases/tag/b10869)（約18MB）から取得します。配布版を固定し、サイズとSHA-256を検証してから配置します。
進捗表示と中止に対応し、完成済みファイルは再利用します。未完成ファイルは残さず、再試行時にダウンロードし直します。配置先は `%LOCALAPPDATA%\rakukan\ai-local` です。
モデルを切り替えたときは、rakukanが起動した別モデルのローカルサーバーだけを停止し、次回生成時に新しいモデルで起動します。軽量モデルも誤った文章を生成する場合があるため、候補を確認してから採用してください。

手持ちの `llama-server.exe` と文章生成用GGUFをファイル選択で指定することもできます。
通常のかな漢字変換用jinenモデルを汎用の文章生成モデルとして扱わないでください。
ローカル要求は思考出力を無効にします。サーバーは初回要求時に非表示で起動し、`127.0.0.1` の設定ポート（既定8081）だけで待ち受けます。
応答準備完了まで待機し、モデルを保持します。設定画面から停止できます。
指定ポートが他プロセスに使われていればエラーにし、停止操作もrakukan自身が起動したサーバーに限定します。

### 外部サーバー

OpenAI互換の `/v1/models` と `/v1/chat/completions` を使用します。
例: `http://gpu-server:8080/v1`。モデル名と、必要ならAPI認証キーを指定してください。
生成時は対象文章・指示・直前候補を指定サーバーへ送ります。自動フォールバックはしません。

## 実装・配布

- `ai.json` は `%APPDATA%\rakukan` に保存します。認証キーは同じフォルダーの `ai-key.bin` にWindows DPAPIで暗号化保存します。
- TSFは別プロセスの `%LOCALAPPDATA%\rakukan\ai\rakukan-ai.exe` へJSONを渡します。アプリ内にHTTPクライアントやモデルランタイムをロードしません。
- AIは通常変換のRPC・共有エンジンロックを使って生成しません。専用の応答チャネルを取り消すことで古い結果を破棄します。
- 通常ログは生成所要時間と失敗種別のみです。AI出力を通常変換の学習へ自動登録しません。
- `scripts/build-settings-winui.ps1` はAI実行プログラムもビルドします。`scripts/install.ps1` とインストーラーにAI実行プログラムを含めます。.NET 8ランタイムが必要です。
- TSF更新後は、既に起動中の入力先アプリを再起動するまで古いDLLが使われる場合があります。

## 検証

```powershell
dotnet run --project apps/rakukan-ai-tests/rakukan-ai-tests.csproj -c Release
cargo test -p rakukan-romaji -p rakukan-tsf --release --lib
# 実機に起動中のCopilotがある場合だけ実行
./scripts/test_copilot_shared.ps1 -Action 6
./scripts/test_copilot_shared.ps1 -Action 1 -Text '今日は晴れです。'
```

自動テストは実モデルを必要としません。分割パイプ受信・不正フレーム・HTTP要求・認証エラー・キャンセル・重複接頭辞・コマンド補正・設定の往復を検証します。
実アプリでは、未確定文／選択範囲、IMEオフからの起動、Enter/Tab/Esc、生成中の補正、フォーカス変更、DPIとテーマを確認してください。
